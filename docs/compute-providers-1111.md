## Picks and placement

**Baseten, Daytona, E2B, Fly Machines** are the first four worker adapters. Baseten meets the explicit request and offers a short promotion; Daytona combines agent/browser tooling with a large trial; E2B has a documented sandbox lifecycle and useful no-card allowance; Fly supplies inexpensive general-purpose Linux VMs with an ordinary REST lifecycle and region selection. GPU inference remains in AI; Run already has RunPod and Vast adapters via SDK. Do not duplicate those ledgers in a new control plane.

For a continuously busy CPU worker, Fly's shared 2-vCPU/2-GiB shape is about $0.018597/hour, compared with Daytona/E2B's 2-vCPU/4-GiB $0.1656/hour and Baseten's $0.2154/hour. These are **different CPU and memory allocations**, not a performance benchmark. At ten active minutes, their base estimates are respectively $0.003100, $0.027600, and $0.035900, before disk, network and subscriptions. Benchmark complete jobs and queue delay before changing defaults.

Run owns placements, leases, reconciliation, reservation locks and deletion. Codes' sandbox workers (`server/domain/sandbox-workers.js`) enforce heartbeat/isolation checks; Tools' `/workers` registry remains in `apps/gateway/server/workers`; Network's machine hub fronts Bot (`server/registry/machines.js`), while cell/node principals stay in Network. Provider images must enroll fresh worker identities through these existing paths. A purchased VM alone is not a healthy worker.

Keep own eligible machines first. Among new rentals, require a current Exchange price, region/resources, allowed kind, prepared image, key, concurrency and positive gross monthly cap. Rank confirmed unexpired credits/promotions first, then the bounded job-duration cost (including deletion allowance and disk/network bound). Unknown purchase/delete outcomes retain reservations and stop retries. Credits never increase the gross spending cap. A promotion expiry stops new purchases and drains running rentals; do not assume the provider automatically stops billing.

## Verification and activation conditions

Research used built-in web search plus direct public provider HTML/Markdown. The ov-deep-research skill's paid Search/Fetch calls were not made because RUNNER-RULES forbids spending money. Some provider pages are JS-only or block fetches; missing values remain explicit. No secondary aggregator price was promoted to an executable quote.

Before turning on a provider: confirm account credits/expiry and quotas, set a positive gross monthly cap and concurrency, choose a current Exchange shape/region, supply a prepared worker image with enforced disk/egress bounds, enroll fresh worker identities, and run dry mode. Shared config secrets require the host's existing encryption-key setup; missing encryption refuses a secret write. Never bake reusable Network credentials into an image. A fake lifecycle test cannot establish real upstream availability, deletion reliability or worker isolation.
